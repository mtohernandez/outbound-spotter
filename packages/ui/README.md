# @outbound/ui

Single source of truth for the shared shadcn/ui surface across `apps/web-app` and `apps/web-auth`. Tokens, primitives, and utility code live here once; apps import, they never duplicate.

## What lives here

| Path                     | Contents                                                                     |
| ------------------------ | ---------------------------------------------------------------------------- |
| `src/styles/globals.css` | The canonical `@theme inline` block, brand OKLCH ramps, light + dark modes   |
| `src/lib/utils.ts`       | `cn()` — the `clsx + tailwind-merge` helper used everywhere                  |
| `src/components/`        | shadcn-installed primitives (Button, Card, Field, …) — generated by the CLI  |
| `src/hooks/`             | Shared cross-app hooks (e.g. `use-media-query`)                              |
| `components.json`        | shadcn config — `tailwind.config = ""` per the Tailwind v4 monorepo guidance |

The `style`, `iconLibrary`, and `baseColor` here are the source of truth — apps' `components.json` files mirror them.

## Adding a component

From within either app:

```bash
cd apps/web-app
pnpm dlx shadcn@latest add button
```

shadcn detects the monorepo via the app's `components.json` aliases and writes the component to `packages/ui/src/components/`. The app gets nothing new in its own tree — just the new export to import.

## Consuming from an app

```tsx
import "@outbound/ui/styles/globals.css";
import { Button } from "@outbound/ui/components/button";
import { cn } from "@outbound/ui/lib/utils";
```

No build step. apps consume the source directly via Vite/TS (JIT-package pattern).

## What does NOT live here

- App routing, providers, env config — those belong in each app's `src/app/`.
- Feature-specific components — those belong in `apps/<app>/src/features/<feature>/components/`.
- Brand logos / illustrations — `apps/<app>/src/assets/`.
