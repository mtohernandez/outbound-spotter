# Code Standards

These rules apply across the monorepo. The architecture invariants in `architecture.md` win over anything here; this file is the next layer down — _how_ to write code that respects those invariants.

## General principles

- **Small modules, single purpose.** A file does one thing. If a function grows past ~60 lines or a component past ~150, split.
- **Fix root causes, not symptoms.** No try/except (or try/catch) that swallows errors. If a code path can fail, decide whether to bubble, retry, or return a typed result.
- **No premature abstraction.** Three similar lines is better than a clever helper. Extract on the _fourth_ duplicate, not the second.
- **No dead code.** No commented-out blocks "for reference," no unused exports, no flags for features that never shipped. Remove it; git remembers.
- **No comments that restate the code.** Names carry meaning. Use comments only for the _why_ — a hidden constraint, a non-obvious invariant, a workaround for a specific bug.
- **Validate at the boundary, trust inside.** Validate user / network input where it enters the system; downstream code assumes the data is sound.
- **No mixing concerns in a single unit.** UI + DB + background work in one PR is a smell. Split per the AI workflow rules.

## TypeScript (web-app, web-auth, shared packages)

- **Strict mode is required.** `"strict": true`, `"noUncheckedIndexedAccess": true`, `"exactOptionalPropertyTypes": true`, `"noImplicitOverride": true`. No project-wide opt-outs.
- **No `any`.** Use `unknown` at boundaries, narrow with type guards or `zod` schemas. Reach for `satisfies` over type assertions.
- **Discriminated unions over boolean flags** for state. `type LogEvent = OnDuty | OffDuty | Driving | Sleeper` beats `type LogEvent = { duty: string; ... }`.
- **`interface` for public object shapes, `type` for unions / utilities.** Either is fine for component props; pick one and stay consistent inside a file.
- **Path alias**: `@/*` → `src/*`. No `../../..` relative imports across feature boundaries.
- **Naming**:
  - Files / folders: `kebab-case` (enforced via ESLint `check-file` plugin).
  - Variables, functions: `camelCase`.
  - Types, interfaces, components, enums: `PascalCase`.
  - Constants of true compile-time literals: `SCREAMING_SNAKE_CASE`. Inferred consts stay `camelCase`.
- **No barrel files** (`index.ts` re-exports). They confuse tree-shaking and obscure source.

## React 19

- **Function components only.** No classes outside error boundaries.
- **Server state lives in TanStack Query** (`@tanstack/react-query` v5+). Client state lives in component state, `useReducer`, or a feature-scoped store (`zustand`) when truly shared. Don't reach for global state by default.
- **No `useEffect` for data fetching.** Use TanStack Query / the route loader. `useEffect` is reserved for synchronizing with external systems (DOM APIs, subscriptions).
- **Lift state by need, not by reflex.** Co-locate state with the consumer; lift only when a sibling needs it.
- **Forms use React Hook Form** + `zod` resolver. The shadcn `Form` / `Field` primitives are the rendering layer.
- **React 19 specifics**: prefer `useActionState`, `useOptimistic`, `useFormStatus`, and the `use()` API where they replace bespoke loading-state hooks. Do not import them defensively when older patterns are cleaner — adopt where they earn their keep.
- **Clerk Core 3 (`@clerk/react` v6)**: use the unified `<Show when="signed-in">` / `<Show when="signed-out">` rather than the legacy `<SignedIn>` / `<SignedOut>` (still exported but deprecated). Hooks: `useUser`, `useAuth`, `useSession`. Import types from `@clerk/react/types` — no separate `@clerk/types` package.
- **Suspense boundaries** at the feature shell, not the component. One `Suspense` per route, fallback is `<SpotterLoader />`.
- **Error boundaries** at the same level as Suspense. Use TanStack Query's error reset hook to recover.

## Bulletproof React layout

Follow [bulletproof-react](https://github.com/alan2207/bulletproof-react) exactly for `apps/web-app/src/` and `apps/web-auth/src/`:

```
src/
├── app/          # routes, app.tsx, provider.tsx, router.tsx (routing layer)
├── assets/       # images, fonts, brand SVGs
├── components/   # shared cross-feature components (incl. ui/ generated by shadcn)
├── config/       # env vars (validated via zod), constants
├── features/     # one folder per feature
├── hooks/        # shared hooks (cross-feature only)
├── lib/          # preconfigured libs (api client, query client, cn, …)
├── stores/       # global state (rare)
├── testing/      # MSW handlers, render helpers, factories
├── types/        # cross-feature TS types
└── utils/        # cross-feature pure utilities
```

Each `features/<name>/` may contain `api/`, `assets/`, `components/`, `hooks/`, `stores/`, `types/`, `utils/`. Only include the folders the feature actually needs.

**Import direction is enforced via ESLint `eslint-plugin-import` rules** (mirrors the upstream Bulletproof config):

- `app/` may import from anywhere except itself recursively.
- `features/<a>/` **may not** import from `features/<b>/` (cross-feature). Sharing happens by lifting to `components/`, `hooks/`, `lib/`, or `packages/`.
- `components/`, `hooks/`, `lib/`, `types/`, `utils/` **may not** import from `features/` or `app/`. They are leaf layers.
- Flow: **shared → features → app**.

## Python (apps/web-api, HOS planner)

- **Python 3.13.** No 3.12-only syntax, no 3.14-only features either (3.13 keeps the widest library parity).
- **Dependency manager: uv** (Astral). Lockfile is `uv.lock`, committed. Use `uv add`, `uv sync`, `uv run`. No `pip install` in scripts; no `requirements.txt` hand-maintained.
- **Type hints everywhere.** Function signatures, dataclass fields, return types. Validated by `uv run mypy --strict` in CI.
- **Use `dataclasses` (with `slots=True, frozen=True` when immutable) or `pydantic` v2 models** depending on whether the value crosses the network. Inside the pure HOS planner, prefer plain frozen dataclasses to keep it Django-free.
- **Lint with Ruff**, format with Ruff's formatter (Black is a fallback only — Ruff is faster and the project default). Settings:
  - Target Python: `3.13`
  - Selected rule sets: `E, F, I, B, UP, SIM, ANN, ARG, RET, S, PL, PERF, RUF`
  - `extend-ignore`: `ANN101`, `ANN102` (self/cls annotations), `S101` (asserts in tests).
- **Type-check with mypy 1.20** (`--strict`). Pinned to the 1.x line until `django-stubs` ships mypy 2 compatibility (the `compatible-mypy` extra currently caps at `<2.1`). The HOS planner ships with full strict typing; Django app code adheres where `django-stubs` allows.
- **Naming**:
  - Modules, packages, functions, variables: `snake_case`.
  - Classes, dataclasses, exceptions: `PascalCase`.
  - Constants: `SCREAMING_SNAKE_CASE`.
- **No bare `except:`.** Catch the specific exception class.
- **No raw SQL** unless parameterized via Django's ORM `.raw()` and reviewed by `security-auditor`.

## Django + DRF

- **App layout**: `apps/web-api/web_api/` is the Django project; feature modules live as Django apps under `web_api/apps/<name>/` (e.g., `trips`, `users`, `logs`). The HOS planner is **not** a Django app — it lives in `web_api/hos/` as plain Python.
- **Settings via `django-environ` / `pydantic-settings`.** No secrets in `settings.py`. `.env.example` documents every variable.
- **Models**:
  - Always set `Meta.indexes` for query patterns used in views; do not rely on auto-indexes.
  - `null=False` is the default; only `null=True` where the column genuinely has no value (not "we'll fill it later").
  - `on_delete` is explicit — pick `PROTECT` unless a clear cascade is intended.
  - Custom managers / querysets live in `<app>/managers.py`; views never write `.filter()` chains longer than 3 calls.
- **ORM hygiene**:
  - `select_related` for FK / OneToOne, `prefetch_related` for reverse / m2m, on every queryset that crosses a serializer.
  - Wrap multi-write paths in `transaction.atomic()` at the view / service layer, never inside the model.
  - Use `bulk_create` / `bulk_update` for batched writes.
- **DRF**:
  - One `ViewSet` per resource; routes via `DefaultRouter`.
  - Serializers do validation; views do orchestration. No business logic in serializers beyond field-shape rules.
  - Pagination: `LimitOffsetPagination` by default (`limit=50`), max `200`.
  - Errors return a consistent envelope: `{ "detail": str, "errors": { field: [str, …] } }`. Use a project-wide exception handler.
  - Auth via `clerk-backend-api` JWT verification; the decoded `sub` is the canonical user id stored on `request.user_id`.
  - OpenAPI schema generated by `drf-spectacular`; checked into `apps/web-api/openapi.yaml`. `packages/api-types` (when created) generates TS from this via `openapi-typescript`.
- **Migrations**:
  - Generated migrations are committed. No squashing once a migration has been deployed.
  - One migration per logical change. No "various tweaks" mega-migrations.
- **HOS module rules** (load-bearing):
  - `web_api/hos/` has **no Django imports**. Verify with a CI grep.
  - Inputs / outputs are plain dataclasses.
  - The planner is deterministic — given the same input, the same `list[LogEvent]` comes out. Unit tested with golden scenarios drawn from `docs/interstate-truck-driver-guide.md` and `docs/assets/example-*.png`.

## API routes (DRF)

- Validate and parse request input before any logic runs.
- Enforce auth + ownership before any mutation: `request.user_id == trip.user_id` or 403.
- Return consistent shapes — see the error envelope above; success returns the serialized resource.
- No long-lived work in request handlers (no LLM calls, no PDF rendering server-side, no email blasts). Use a background task pattern when those land.
- ORS calls go through `web_api/integrations/openrouteservice.py` only. Never inline.

## Styling

- **Tailwind v4 only.** CSS-first config in `globals.css`. No `tailwind.config.ts`.
- **Semantic tokens only.** See `ui-context.md`. No hex literals or `bg-blue-500`-style raw colors in components.
- **Border radius 0.** Per `ui-context.md`.
- **No `space-x-*` / `space-y-*`.** Always `flex` + `gap-*`.
- **`size-*` over `w-* h-*`** when width equals height.

## Data + storage

- Metadata in Postgres. No file storage in v1.
- ORS responses are cached in `trip_route_cache` keyed by `sha256(current|pickup|dropoff|cycle_hours)` so the reviewer can re-run a trip without burning the daily quota.
- Migrations live in their Django app's `migrations/` folder. Never edited by hand once applied to any environment.

## Testing

- **Python** — pytest 9 + pytest-django 4.12 + factory_boy 3:
  - Test files: `tests/test_<unit>.py`. Test classes optional; functional style preferred.
  - Use factories for fixtures, not `create()` literals.
  - HOS planner has its own `tests/test_hos_<scenario>.py` set with named, regulation-cited golden scenarios. Adding a regulation interpretation requires a new golden test, no exceptions.
  - Database access via `@pytest.mark.django_db`. Default to no DB unless the test needs one.
- **TypeScript** — Vitest 4 + Testing Library 16:
  - Test files: `*.test.ts` / `*.test.tsx` colocated next to the unit.
  - Use `userEvent` from `@testing-library/user-event`, not `fireEvent`.
  - Query order: `getByRole` > `getByLabelText` > `getByText` > `getByTestId` (last resort).
  - Mock the network via MSW (`src/testing/handlers.ts`), not by stubbing the fetch API.
- **AAA** pattern (Arrange / Act / Assert) with a blank line between each.
- **No e2e in v1** (per `architecture.md`). Add Playwright later if needed.

## Imports + module organization

- ESLint `import/order` sorts: builtins → external → internal aliases (`@/*`) → parent → sibling → index. Blank line between groups.
- `pnpx eslint --fix` resolves disorder; Husky pre-commit hook runs it.
- One named export per file when the file is named after the export (the React-component file pattern). Multiple smaller utilities can co-exist in `utils/<topic>.ts`.

## Commit + branch conventions (gitflow)

- **Long-lived branches**: `main` (production), `develop` (integration).
- **Per-unit branches**: `feat/NN-feature-slug` or `fix/NN-bug-slug`, off `develop`. Open a PR back into `develop`.
- **Conventional commits**: `feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`, `perf:`, `build:`, `ci:`. Scope optional but useful (`feat(web-api): …`).
- **No `--no-verify`** to bypass hooks. If a hook fails, fix the cause.
- **Squash or rebase merge** into `develop`; merge-commit only into `main` from a release branch.
- **PRs require**:
  - Description with the spec number it implements.
  - Verification checklist from the spec, ticked.
  - Passing CI (lint, typecheck, tests, build).
  - `code-reviewer` agent (from `comprehensive-review` plugin) sign-off — see `ai-workflow-rules.md`.

## Tooling versions

Defined in `architecture.md` "Stack versions". When a dependency goes out of date, _first_ update `architecture.md`, then update the manifests. The spec for the version-bump unit references both.

## Source files that are off-limits to edit

- `apps/web-app/src/components/ui/*` and `apps/web-auth/src/components/ui/*` — generated by `shadcn add`. Re-run the CLI to update; do not hand-edit.
- `apps/web-api/openapi.yaml` — generated by `drf-spectacular`. Regenerate when the API changes.
- Any file inside `.agents/skills/<name>/` or `~/.claude/plugins/` — installed by the skills / plugin tooling.
- `pnpm-lock.yaml`, `uv.lock` (or equivalent) — let the package manager write these. Commit the result; don't merge-edit them.
- Migration files after they've been applied to any environment.
