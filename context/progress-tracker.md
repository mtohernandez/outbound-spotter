## Architecture Decisions

- 2026-05-19 — **Spec order reshuffled at spec-03 authoring time.** Reason: the FMCSA-mandated trip-input surface (three addresses + cycle hours + submit) is harder UX work than the HOS planner and unblocks user testing of the form earlier; letting the HOS planner land against the real form (not a hypothetical one) also lowers the chance of planner-to-form mismatch. New order: `03 = trip input + shell` (this spec), `04 = ORS Directions + Trip model upgrade` (replaces the stub), `05 = HOS planner foundation` (formerly spec 03). The HOS planner remains a pure-Python module per architecture invariant #1 when its turn lands.
- 2026-05-19 — **Spec 03 ships as a single FE+BE vertical slice.** Reason: `context/ai-workflow-rules.md#Scoping rules` says split FE/BE into ordered units, but the BE half here is limited to thin Pelias proxy endpoints (`/api/geocode/{autocomplete,search}/`) + a stub `POST /api/trips/` echo — there is no Trip business logic, no HOS, no ORS Directions in this unit. Splitting would force a contract-only intermediate spec with zero user-visible value. The deviation is recorded inline in the spec's Boundary section so senior review sees it intentionally.
- 2026-05-19 — **Custom `NavUser` profile bubble, not Clerk's `<UserButton />`.** Reason: the brand owns its identity surface and the bubble must also host our `ThemeToggle` (`<UserButton />` does not surface custom menu items in Core 3 without unsupported workarounds). Built from shadcn `Avatar` + `DropdownMenu` hydrated by `useUser()` + `useAuth()` from `@clerk/react`. `useAuth().signOut()` powers Sign out. Same primitives + composition will be reused in future shells (account settings, mobile sheet).
- 2026-05-19 — **`sidebar-09` is reference inspiration only; we ship a single icon-collapsible rail.** Reason: shadcn's `sidebar-09` is a dual-nested mail layout (icon rail + content panel of mail items). The trip planner has no list-pane consumer yet (Saved Trips is queued for spec 09), so a second panel would be empty. Single-rail `<Sidebar collapsible="icon">` is the right MVP shape; the layout can extend to a dual-rail later by composing a second `<Sidebar>` without rewriting the first.
- 2026-05-19 — **Address resolution = autocomplete-as-you-type via a server-side Pelias proxy.** Reason: live autocomplete is materially better UX than resolve-on-blur (UI.md §3.1) and the architecture invariant #3 mandates the API key stay server-side. Tradeoff: heavier on the HeiGIT standard-plan geocoding quota (~1000 req/day) — mitigated by a 250 ms client-side debounce + TanStack Query `staleTime: 5 * 60_000` dedupe. Pelias confidence (0–1) + the resolved `lat/lon` are stamped onto the form state at selection time; free-text addresses are rejected by zod at submit-time.
- 2026-05-19 — **Two-spec split for the auth experience.** Reason: `context/ai-workflow-rules.md`'s "one system boundary per unit" rule. Spec 01 lands shared primitives in `packages/ui` (the UI source of truth per `CLAUDE.md`); spec 02 builds the three custom Clerk flows on top inside `apps/web-auth`. Rejected: a single combined spec — would have mixed two boundaries and required two verification paths.
- 2026-05-19 — **Mirror the auth background video with responsive `<source>` tags + poster.** Reason: removes a third-party CDN dependency and gives us a predictable LCP via the poster image (per <https://web.dev/articles/lcp>). Combined desktop + mobile + poster ≤ ~5 MB; encoded with `ffmpeg -movflags +faststart` so streaming starts immediately.
- 2026-05-19 — **Inline email-code verification on `/sign-up`.** Reason: matches Clerk's `email_code` example, avoids a route-change/redirect cycle, and lets focus management move directly to the OTP cell without losing in-progress form state.
- 2026-05-19 — **MFA (TOTP / SMS / backup codes) is out of v1 scope.** Reason: matches `project-overview.md`'s v1 in-scope list (single driver, no admin role). "High-end security" still holds via Clerk Turnstile bot protection, zxcvbn-ts strength gating, and the HaveIBeenPwned (`form_password_pwned`) compromised-password check. Revisit after launch.
- 2026-05-19 — **Clerk instance configuration is owned by the session via the `clerk` CLI, not by the user.** Reason: env vars already hold real instance keys, so the implementer can drive SSO connections, bot protection, password rules, and redirect-URL allowlists directly through the Clerk Backend / Platform API. Eliminates the manual-dashboard handoff and lets the PR body capture the exact instance state via CLI output.
- 2026-05-19 — **End-to-end testing is performed by the session-attached Playwright MCP, not by committed Playwright source.** Reason: E2E coverage must drive a real browser as a real user, but the project does not need (and `architecture.md` does not pin) `@playwright/test` as a repo dependency. - 2026-05-19 — **`exactOptionalPropertyTypes: false` in `packages/ui/tsconfig.json` + `apps/web-app/tsconfig.app.json`.** Reason: shadcn-generated `dropdown-menu.tsx` and `slider.tsx` spread `{...props}` containing `checked: CheckedState | undefined` / `value: number[] | undefined` into Radix primitives that don't accept explicit `undefined` under the strict flag. Per the spec-01 precedent for ESLint ("adapt the linter, not the generated code"), we relax the TS flag for the packages that source-consume shadcn primitives. The shared `@outbound/typescript-config/base.json` keeps the flag on — only the two consumers opt out.
- 2026-05-19 — **`BrandMark` gains a `variant="icon"`** (spec 03 / round-1 code review). Reason: the existing `mark-only` variant only swapped the palette to `currentColor` while keeping the full `385×128` wordmark — useless for an icon-rail header where the available width is `3rem`. UUIDv4's 122-bit entropy makes brute-force impractical, but the principle matters once we lift to integer ids or sequential identifiers. Single `Trip.objects.filter(pk=id, user_id=request.user_id).first()` query — same plan, no oracle.
