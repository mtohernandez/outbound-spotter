# 01 — Shared UI Foundation

> The first implementation unit. Lands every shadcn primitive, brand artifact, and theme primitive in `packages/ui/` so spec 02 (and every later spec) imports from a single source of truth. No app-level files change in this unit; the auth screens come next.

## Goal

Ship the shared UI foundation in `packages/ui` so the project's UI source-of-truth contract from `CLAUDE.md` (_"The shared UI source of truth is `packages/ui`. Apps import primitives + theme; they never re-implement."_) is real, not aspirational. Outputs: shadcn primitives, a brand-mark component, an animated SpotterLoader, a `ThemeProvider` / `useTheme` / `ThemeToggle` trio, and a Vitest + RTL harness in `packages/ui`.

## Scope

### In

- shadcn primitives installed into `packages/ui/src/components/ui/` via the shadcn CLI (new-york style, latest).
- `BrandMark` (typed React import of `outbound-logo.svg`, monochrome `currentColor` variant).
- `SpotterLoader` (animated, pure SVG + CSS, no JS).
- `ThemeProvider`, `useTheme`, `ThemeToggle` — `.dark` class strategy on `<html>`, persisted to `localStorage`, respects `prefers-color-scheme`.
- Vitest 4 + Testing Library 16 + jsdom harness, colocated `*.test.tsx`.
- One new asset folder: `packages/ui/src/assets/brand/`.

### Out (deferred)

- App routes and Clerk flows — `02-clerk-auth-screens.md`.
- Storybook — not in v1 (verified via the auth screens once they exist).
- Internationalization, RTL.
- Anything HOS / map / log SVG.
- ChartContainer, DataTable, Calendar, and other primitives we have no consumer for yet (per `code-standards.md#No premature abstraction`).

## Sequencing

### Step 1 — Install shadcn primitives

Run the shadcn CLI from the workspace root (or from one of the apps; both `components.json` files retarget output to `packages/ui`):

```bash
pnpm dlx shadcn@latest add button input label card form separator alert skeleton badge sonner toggle
```

Verify the output path: every primitive lands in `packages/ui/src/components/ui/` (not in either app). The CLI also installs `@radix-ui/*` peer deps into `packages/ui/package.json` — let it. Do not hand-edit any file under `packages/ui/src/components/ui/` after generation; per `code-standards.md`, those files are CLI-owned and re-run-to-update.

Cite the CLI in the PR body: <https://ui.shadcn.com/docs/cli>.

`sonner` is the toast primitive. `form` brings `Field`, `FieldLabel`, `FieldError`, `FieldGroup`, `FieldDescription` — those are the form composition contract referenced by `context/ui-context.md` and the `shadcn` skill. `toggle` is needed by the dark-mode switch.

### Step 2 — Brand assets and components

1. Copy `docs/assets/outbound-logo.svg` to `packages/ui/src/assets/brand/outbound-logo.svg`.
2. Copy `docs/assets/spotter-logo-loader.svg` to `packages/ui/src/assets/brand/spotter-loader-base.svg`.
3. Configure SVGR for `*.svg` imports in `packages/ui` via Vite (or `@svgr/rollup` if `packages/ui` builds with `tsup`/`tsc`). Confirm the actual build tool by reading `packages/ui/package.json` `scripts.build` — match its bundler. Cite SVGR docs: <https://react-svgr.com/>.
4. Author `packages/ui/src/components/brand/brand-mark.tsx`:
   - Default export: `BrandMark` — renders the imported logo SVG with `fill="currentColor"` so it inherits `text-foreground`.
   - Prop `variant`: `"full" | "mark-only"`; default `"full"`.
   - Prop `aria-label` (overrideable; default `"Outbound Spotter"`).
   - Use `forwardRef<SVGSVGElement>` so the consumer can attach refs / `data-icon` slots.
   - No hex literals in the wrapper. The brand SVG itself ships brand colors, but the monochrome variant overrides `fill="currentColor"` on every `<path>` via SVGR's `replaceAttrValues` config — wire that in SVGR config, not the component.

5. Author `packages/ui/src/components/brand/spotter-loader.tsx`. The animation contract:
   - Renders the four base circles from the spotter logo at their original positions (red at top-left, teal at bottom-left, two light-blue at bottom-middle and bottom-right).
   - Animation cycle (~1.2 s total) loops indefinitely:
     - **Phase A (~600 ms, `cubic-bezier(0.4, 0, 0.2, 1)`)** — the red circle at the top translates left → right along the top axis to a position above the bottom-right circle.
     - **Phase B (~400 ms, `cubic-bezier(0.4, 0, 0.2, 1)`)** — the red circle drops onto the bottom-right position; simultaneously, all bottom circles shift one slot to the right via translate; the previously-right-most light-blue circle "wraps" to bottom-left.
     - **Phase C (~200 ms, `ease-out`)** — the bottom-left circle pops up to the top-left position, restoring the base layout one circle further around the loop. Loop restarts; the cycle visually conveys _circles taking turns rotating around the brand pattern_.
   - Implementation constraint: **pure SVG + CSS keyframes**. No JS state, no `<animateTransform>` if CSS suffices (it does — `transform: translate()` on inline SVG is well-supported per <https://developer.mozilla.org/en-US/docs/Web/CSS/transform>).
   - Honors `prefers-reduced-motion: reduce` — animation pauses at the base state (no movement). Tested via `window.matchMedia("(prefers-reduced-motion: reduce)").matches` in unit tests using `vi.stubGlobal('matchMedia', …)`. Cite the W3C technique: <https://www.w3.org/WAI/WCAG22/Techniques/css/C39>.
   - API:
     - `size?: "sm" | "md" | "lg"` (default `"md"`; pixel sizes 16 / 24 / 40 respectively — match the dense control sizes in `context/ui-context.md`).
     - `aria-label?: string` (default `"Loading"`).
     - `role="status"` on the wrapping `<span>` so assistive tech announces it.
     - When used inside a shadcn `Button` (`buttonVariants` supports `data-icon`), size collapses to the icon-slot size.

6. Re-export both brand components via named export from their own files. **No barrel file** (`code-standards.md` forbids them).

### Step 3 — Theme primitives

Under `packages/ui/src/components/theme/`:

1. `theme-provider.tsx`:
   - React context: `{ theme: "light" | "dark" | "system"; resolvedTheme: "light" | "dark"; setTheme: (t) => void }`.
   - Reads initial value from `localStorage["outbound-theme"]`, falls back to `"system"`.
   - On mount, applies `.dark` class on `document.documentElement` based on `resolvedTheme`.
   - Subscribes to `window.matchMedia("(prefers-color-scheme: dark)")` `change` events when `theme === "system"`.
   - SSR-safe: writes to `document` only inside `useEffect` (the project is Vite-CSR, but the component should remain SSR-safe for any future migration).
   - Accepts `defaultTheme` prop (defaults to `"system"`).
2. `use-theme.ts`: exports `useTheme()` returning the context value. Throws if used outside the provider.
3. `theme-toggle.tsx`:
   - Renders a shadcn `Button variant="ghost" size="icon"`.
   - `aria-pressed={resolvedTheme === "dark"}`.
   - Label remains constant (`"Toggle theme"`) per the W3C APG button-toggle pattern; only the icon swaps between `Sun` and `Moon` from `lucide-react`. Cite: <https://www.w3.org/WAI/ARIA/apg/patterns/button/>.
   - On click: cycles `light` → `dark` if currently `"system"` with resolved `light` (and vice versa), then explicit toggling thereafter.
   - The button visually shows the icon for the _next_ mode (so a sun is visible when about to switch to light). The tooltip / `aria-label` says `"Switch to {next} theme"` (computed) but the _visible_ label and `aria-label` of the toggle stay consistent across renders to avoid screen-reader thrash; use `aria-pressed` to convey state, not the label.

Decision recorded for senior review: we use `aria-pressed` rather than `role="switch"` + `aria-checked` because the APG examples for "two-state buttons" (which is what a theme toggle is) prefer `aria-pressed`. `role="switch"` is reserved for primitives with a visible track/thumb metaphor.

### Step 4 — Test harness

1. Add dev deps via pnpm:

   ```bash
   pnpm add --filter @outbound/ui -D vitest jsdom @testing-library/react @testing-library/user-event @testing-library/jest-dom @vitejs/plugin-react
   ```

   Pinned versions match `context/architecture.md`'s `Testing` row: Vitest **4.x**, RTL **16.x**. Verify against npm at install time: `npm view vitest version` and `npm view @testing-library/react version`. Cite in the PR body.

2. `packages/ui/vitest.config.ts`:
   - `environment: "jsdom"`.
   - `setupFiles: ["./src/test/setup.ts"]`.
   - `plugins: [react()]`.
   - `resolve.alias`: `@` → `./src`.

3. `packages/ui/src/test/setup.ts`:
   - `import "@testing-library/jest-dom"`.
   - `vi.stubGlobal("matchMedia", …)` mock factory exported for component tests.

4. Add `test` script to `packages/ui/package.json` (`"test": "vitest run"`, `"test:watch": "vitest"`). Confirm `turbo.json` `test` task picks it up via the existing pipeline.

5. Colocated unit tests (minimum coverage gate — every test must use AAA structure per `code-standards.md`):
   - `brand-mark.test.tsx` — renders SVG; respects `aria-label`; inherits `currentColor`; `forwardRef` works.
   - `spotter-loader.test.tsx` — renders four circles; respects `prefers-reduced-motion` (animation paused); applies size variant classes; `role="status"` present; aria-label defaults to `"Loading"`.
   - `theme-provider.test.tsx` — initial theme from localStorage; falls back to system; setTheme writes to localStorage; `.dark` class toggles on `<html>`.
   - `use-theme.test.tsx` — throws outside provider; returns context inside.
   - `theme-toggle.test.tsx` — `aria-pressed` mirrors theme; click toggles state and `.dark` class; label stays constant across toggles.
